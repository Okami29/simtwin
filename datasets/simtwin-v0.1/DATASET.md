# SimTwin v0.1 experiment dataset

Synthetic datasets produced by **SimTwin** v0.1.0, a digital-twin
simulator for networked FDM/FFF additive-manufacturing fleets.

Everything here is **synthetic**. It is generated by a seeded simulator, so every
row is reproducible from the code and the recorded seed. Nothing was collected from
a physical machine, and no device, operator or customer data is present.

## The E4 fault-injection dataset

The ML-ready artifact: two matched runs of the same 60-device fleet over 14,400 s
(4 h) at $\Delta t = 1$ s.

* **baseline** — no faults injected (seed 405).
* **faulted** — all 11 catalogue faults injected by a Poisson process at 6 faults
  per machine-hour, 1,462 episodes (seed 404).

`telemetry_*.parquet` carries one row per device per telemetry tick — 864,000 rows,
20 columns: device id, simulated timestamp, finite-state-machine state,
nozzle/bed/chamber temperature, power, cumulative material use, print speed, health
score, active fault code and severity, and twin-side delivery bookkeeping.

`separability.csv` is the derived label-free separability table: per-channel
Cohen's *d* and per-channel Mann--Whitney AUC between fault-active and fault-free
`PRINTING` samples, for every fault.

### Loading it

```python
import pandas as pd
t = pd.read_parquet("E4_fault_injection/telemetry_faulted.parquet")
d = pd.read_csv("E4_fault_injection/separability.csv")
```

## Provenance

Each run's `metadata.json` (mirrored as `metadata_*.json`) records the fully
resolved configuration, the seed, the injected-fault summary, the per-file artifact
manifest, the run metrics, and the captured environment: OS release, machine and
processor, logical CPU count, total memory, Python implementation and version, and
the pinned version of every dependency.

Environment used for this release: Darwin 25.6.0, arm64, Apple M3 Pro, 11 logical
CPUs, 18 GiB RAM, CPython 3.13.0, NumPy 2.5.3, Mosquitto 2.1.2 (E7 only).

## Determinism

Runs are a pure function of (configuration, seed). Randomness comes from
independent named NumPy streams spawned from one `SeedPlan`, so adding a consumer of
randomness in one subsystem cannot shift the stream in another. E6 verifies this at
the artifact level: two runs at seed 2027 produce telemetry with identical SHA-256
digests, and a run at seed 2028 produces a different digest.

The one exception is the MQTT broker transport (E7): real broker latency is
wall-clock, so it is not bit-reproducible. E7 reports delivery, latency and
staleness distributions, not digests.

**Wall-clock columns are not reproducible constants.** `wall_clock_s`,
`realtime_factor`, `device_steps_per_second`, `telemetry_throughput_msg_s` and the
RSS columns are live measurements on a general-purpose laptop and move 10-20 %
with background load. The simulated physics behind them is exact; the timings are
indicative.

## Bibliography audit

`bibliography_verification.json` records the Crossref resolution of every
bibliography entry in the accompanying manuscript: the query, the resolved record,
and the fields corrected. `bibliography_dropped.json` lists the entries removed
because they could not be resolved at all, with the reason for each.

## Regenerating it

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python experiments/run_all.py           # all experiments
.venv/bin/python experiments/make_figures.py       # figures and tables
```

E7 skips itself (writing a summary row that says so) unless an MQTT broker is
listening on 127.0.0.1:1883. Start one with `mosquitto -p 1883`.
